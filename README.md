Русская редакция плагина [`dsh-user-mirror`](https://www.npmjs.com/package/dsh-user-mirror)
(исходники апстрима: [webkubor/dsh-mirror](https://github.com/webkubor/dsh-mirror), версия **0.6.1**).

Переведён весь видимый текст — вкладка «Память», справка, описания инструментов, тексты
ошибок и блок накопленной памяти в системном промпте. Сверх перевода в форке **две правки
самого плагина**: без них русская память работает неправильно — счётчики врут, а записи
копируются дублями, потому что апстримный сопоставитель тем не умеет кириллицу.

* Англоязычная выжимка (ради чего это нужно не только русскоязычным) — [README.en.md](README.en.md).
* Инструкция для ИИ-агента: установка, проверка, откат — [AGENTS.md](AGENTS.md).

## Что делает плагин

Плагин закрывает одну задачу: **модель сама записывает, как думает этот человек**, и эти
записи возвращаются в системный промпт следующих сессий.

* **Учится.** Когда человек высказывает переносимое суждение («не платить сложностью за
  несрочную задачу», «в CI мне нужны архивы логов, а не скриншоты»), модель вызывает
  инструмент `mirror_remember` и **записывает, почему запомнила**.
* **Помнит.** Записи хранятся локально через `ctx.storageDomain` — с пределом ёмкости,
  забыванием по кривой забывания и перезаписью по теме.
* **Использует.** Накопленное вставляется в системный промпт по бюджету **токенов**, а не
  «по количеству записей».

Записываются только суждения, а не факты: пути, аккаунты, адреса серверов и репозиториев
имеют собственный источник истины, и вторая копия здесь рано или поздно разошлась бы с ним.

| Категория | Что в неё попадает |
|---|---|
| `principle` | принцип/компромисс — что предпочесть и как выбирать в какой ситуации |
| `redline` | красная линия — чего делать нельзя ни в коем случае |
| `workflow` | рабочий процесс — порядок работы и привычки взаимодействия |
| `taste` | вкус/подача — формулировки, стиль, подача |

Инструменты: `mirror_remember(text, kind, reason)` — записать, `mirror_forget(text, reason)` —
убрать запись по смыслу (точный текст помнить не нужно). Инструмента чтения нет намеренно:
память и так лежит в системном промпте, второй путь чтения только занимал бы постоянные токены.

## Требования

| Что | Значение |
|---|---|
| DSH | ≥ `0.1.1-rc.2`; разработка и проверка — на `0.1.5-rc.2` |
| Профиль | **только `web`**: плагину нужны сервисы `storageDomain` и `webServer`. На headless-профиле он уходит в `pending (waiting for services)` и валит загрузку |
| git и pnpm | нужны для установки из git: `dsh plugin` — тонкая обёртка над `pnpm`, запускаемой в каталоге профиля |
| Node | тот, на котором работает сам DSH |

Форк и апстрим — **один и тот же пакет** (имя `dsh-user-mirror`), ставится он **вместо**
апстрима, а не рядом. Двух копий быть не должно: они регистрируют одни и те же маршруты
и инструменты.

## Установка (человеку)

Нужен установленный и хотя бы раз запущенный DSH с профилем `web`.

```powershell
# 1. посмотреть, что стоит сейчас (не обязательно, но полезно)
dsh plugin --profile web why dsh-user-mirror

# 2. поставить русскую редакцию из репозитория
dsh plugin --profile web add github:Danerus23/dsh-user-mirror-ru

# 3. перезапустить профиль web, затем обновить страницу в браузере с Ctrl+Shift+R
```

Шаг 2 **заменяет** зависимость профиля: если раньше стояла версия из npm, она уезжает, а
на её место встаёт git-адрес форка. Команда сама дописывает пакет в `dsh.profile.bundles`
профиля — руками править `package.json` не нужно.

Перезапуск: если DSH запущен из терминала — `Ctrl+C` и снова `dsh web`; если через панель
(трей) — «Остановить», затем «Запустить». Плагин читается на старте, поэтому без перезапуска
изменений не будет.

### Если git недоступен, а нужен только перевод

Есть запасной способ: наложить файлы перевода поверх **уже установленного** npm-пакета.
Он не трогает `package.json`, но и не защищает от обновления — `dsh plugin update` затрёт
накат, и скрипт придётся запустить заново.

```powershell
git clone https://github.com/Danerus23/dsh-user-mirror-ru.git
cd dsh-user-mirror-ru
pwsh -File .\tools\apply-overlay.ps1          # накат (с бэкапом и поведенческими тестами)
pwsh -File .\tools\apply-overlay.ps1 -Revert  # вернуть как было
```

Скрипт откажется работать, если установлен апстрим другой версии (перевод сверяется по
коду), — тогда нужен `-Force` или перенос перевода на новую версию.

## Как убедиться, что всё встало

1. Откройте в интерфейсе вкладку **«Память»** — она появляется после «Чат / Траектория».
   Подписи должны быть русскими: «Память», «предпочтения, выученные из цепочки think ·
   забываются · новое переписывает старое», «Когда оно записывает? Что именно? Почему
   забывает?».
2. Если подписи китайские — почти всегда это **старый бандл из кеша браузера**:
   обновите страницу с `Ctrl+Shift+R`. Если не помогло — профиль не перезапускался.
3. Из клона репозитория можно проверить и командой (маршруты плагина и язык подписей):

```powershell
pwsh -File .\tools\check-server.ps1                       # по умолчанию http://127.0.0.1:3080
pwsh -File .\tools\check-server.ps1 -Url http://127.0.0.1:3097
```

## Обновление

```powershell
dsh plugin --profile web update dsh-user-mirror
```

Обновляется **то, что стоит**: с git-адресом это форк, и перевод никуда не денется.

Если репозиторий форка обновился, а pnpm этого не заметил:

```powershell
dsh plugin --profile web add github:Danerus23/dsh-user-mirror-ru
```

Ветку и коммит можно зафиксировать: `github:Danerus23/dsh-user-mirror-ru#v0.6.1-ru.1`.

## Удаление и возврат к апстриму

```powershell
# вернуться к версии из npm
dsh plugin --profile web remove dsh-user-mirror
dsh plugin --profile web add dsh-user-mirror

# или убрать плагин совсем
dsh plugin --profile web remove dsh-user-mirror
```

Память при этом не удаляется: записи лежат в хранилище DSH (домен `dsh_mirror`), а не
внутри пакета. Вкладка «Память» исчезнет вместе с плагином.

## Правки к апстриму

Перевод сам по себе — не единственная причина для форка. Обе правки нашлись на живом
сервере и обе меняют поведение.

### Правка 1: запись и удаление памяти теперь дождаются завершения

`table.put` / `table.delete` в `@deepseek-ai/dsh-storage-domain` асинхронные: они
возвращают промис и выполняют работу в очереди. Апстрим вызывает их без `await` и сразу
читает `table.size` — то есть состояние «до».

```js
table.put(id, { ... })                             // добавление
return { outcome: 'created', total: table.size }   // size ещё старый
```

Отсюда три следствия:

1. **Врали оба счётчика.** `mirror_remember` печатал «всего записей: 0» сразу после первой
   записи, `mirror_forget` — «осталось 1» после удаления единственной.
2. **Вытеснение по пределу ёмкости не срабатывало на только что добавленной записи** —
   `table.size` в проверке `if (table.size > config.maxPreferences)` её ещё не видел.
3. **Запись на диск не дожидалась ответа**: закрыв процесс сразу после операции, можно было
   не получить ни добавления, ни удаления.

Исправлено везде: `remember()` стала `async` и ждёт `put` (обе ветки — перезапись по теме и
добавление) и `delete` (вытеснение), инструмент `mirror_remember` ждёт `remember()`,
`mirror_forget` и HTTP-обработчик `/dsh-mirror/forget/<id>` ждут `table.delete()`.

### Правка 2: сопоставитель тем понимает кириллицу

Апстрим искал сущности по `/[a-z0-9]+/g` — кириллица туда не попадала вообще, а второй канал
сравнивает иероглифические биграммы. То есть для русских записей не работал **ни один** канал,
кроме дословного совпадения: «русские ответы» и «отвечать по-русски» считались разными темами
и копились дублями до предела ёмкости.

| Что добавлено | Как |
|---|---|
| Кириллица в сущности | `/[a-z0-9\u0430-\u044f\u0451]+/g` |
| Русские стоп-слова | 186 служебных слов и частых глаголов: без них канал слов склеивал бы разные записи по общим «для», «что», «использовать» |
| Срезание «пользователь» | `normalize()` и оба extract'а — аналог апстримного `/^\u7528\u6237/`; модель часто начинает запись со слова «пользователь» |
| Канал русских основ | `extractStems()`: первые 5 символов слова — «русски» / «русские» / «русском», «картинки» / «картинок» |

Первая версия канала срезала окончания по списку — и на живой проверке выяснилось, что это
даёт **разные** основы для одного корня: «русски» → `русс` (срезалось «ки»), «русские» →
`русск` (срезалось «ие»), из-за чего тема не опознавалась. Поэтому основа — просто первые
5 символов слова: результат не зависит от того, какое окончание попалось первым в списке.

**Известная граница:** жёсткая морфология не сводится — «отвечай» и «ответы» дают разные
пятисимвольные основы, поэтому пара, где это единственное общее слово, не склеится. Пять
символов, а не четыре: на четырёх «предпочитать» и «предлагать» дали бы ложную склейку, а
ложная склейка тут дороже дубля — она стирает чужую запись. Полноценное решение — стеммер или
embedding, как и пишет апстрим про свои границы.

## Что переведено

| Где | Что |
|---|---|
| Вкладка «Память» | заголовок, подпись, кнопка «Обновить», пустое состояние, «Загрузка…», «Не удалось загрузить» |
| Каждая запись | «почему записано», «сила», «подтверждений», «только что / N минут назад / N часов назад / N дней назад», тултип кнопки удаления и её двухшаговое подтверждение |
| Раскрывающаяся справка | «Когда записывает? Что именно? Почему забывает?» — все пункты |
| Категории | `principle` / `redline` / `workflow` / `taste` — русские подписи в легенде и в ответе `/dsh-mirror/preferences` |
| Инструменты | описания `mirror_remember` и `mirror_forget`, тексты их ответов и ошибок |
| Системный промпт | секция, которую видит модель: `(mirror: …)` и блок с накопленной памятью |
| Прочее | статусы шарика ai-orb (включая aria-подписи), сообщения лога `ctx.logger`, комментарии |

## Что сознательно не переведено

* имена инструментов и параметров (`mirror_remember(text, kind, reason)`) — это API;
* пути и URL (`/dsh-mirror/preferences`, `/dsh-mirror/forget`, `/dsh-mirror/vendor/ai-orb`);
* имя slot `conversation.view`, CSS-классы, идентификаторы, `package.json`;
* **данные сопоставителя тем**: срезание ведущего «用户», китайские служебные слова,
  выделение иероглифических сегментов `[^\u4e00-\u9fa5]`. Это алфавит сравнения, а не проза:
  перевод сломал бы дедупликацию молча. Русские правила добавлены рядом, китайские остались.

## Настройки

Параметры переопределяются в патче профиля (`~/.dsh/profiles/web/cordis.patch.yml`) — так же,
как это описано в апстриме:

```yaml
- insert:
    - id: dsh-mirror
      name: dsh-user-mirror
      config:
        maxPreferences: 20   # предел ёмкости памяти, записей
        halfLifeDays: 30     # период полураспада, дней: сколько не подтверждается — слабеет
        maxTokens: 500       # бюджет вставки в системный промпт, токенов
        sectionOrder: 160    # место секции в системном промпте (меньше — раньше)
```

## Приватность

* память хранится только локально (`~/.dsh/storages/`), никуда не отправляется;
* плагин не ходит в сеть;
* очистить память — удалить домен `dsh_mirror` в хранилище DSH.

## Состав репозитория

Корень репозитория — сам пакет: то, что ставится из git, лежит в корне.

| Путь | Что это |
|---|---|
| `index.js` | **рабочий** файл host-половины: перевод + правки; собирается скриптом из `index.translation.js` |
| `client.js` | браузерная половина, чистый перевод |
| `cordis.patch.yml` | патч bundle-профиля: вставляет плагин в web-профиль |
| `index.translation.js` | чистый перевод host-половины — эталон для сверки с апстримом |
| `upstream/0.6.1/` | нетронутые файлы апстрима из npm: база для сверки и для переноса перевода на новую версию |
| `tools/build-index.mjs` | правки как список якорей: сборка `index.js` (`--check` — только проверка) |
| `tools/verify-structure.mjs` | сверка перевода с апстримом по скелету кода и рабочего файла с переводом |
| `tools/test-matcher.mjs` | поведенческие тесты сопоставителя тем (22 проверки) |
| `tools/apply-overlay.ps1` | накат перевода поверх npm-пакета с бэкапом и автооткатом |
| `tools/check-server.ps1` | проверка живого сервера: маршруты и русские подписи категорий |
| `tools/link-deps.ps1` | junction-ы на зависимости профиля — чтобы тесты шли из клона |

## Как это проверяется

```powershell
node tools/verify-structure.mjs     # перевод == апстрим по скелету; index.js == перевод + правки
node tools/test-matcher.mjs         # 22 поведенческие проверки сопоставителя
pwsh -File tools/check-server.ps1   # живой сервер: маршруты и русские подписи категорий
```

`tools/link-deps.ps1` нужен только для тестов из клона: он ставит junction-ы на зависимости
профиля, чтобы Node нашёл `@deepseek-ai/*`, `zod` и `ai-orb`. Важно, что это **те же самые**
копии, что и в бою: две копии `dsh-tools` ломают DSH целиком.

## Обновление апстрима

Когда выходит новая версия `dsh-user-mirror` в npm, перевод переносится вручную:

1. положите новые файлы апстрима в `upstream/<новая версия>/` и сравните их с прежними —
   видно, что изменилось;
2. перенесите изменения в `index.translation.js` (и, если затронуто, в `client.js`);
3. проверьте, что якоря в `tools/build-index.mjs` всё ещё находятся (сборка сообщит, если нет);
4. поднимите `version` в `package.json` (`<версия апстрима>-ru.<сборка>`), дополните
   `CHANGELOG.md` и историю апстрима в `upstream/`;
5. прогоните `tools/verify-structure.mjs` и `tools/test-matcher.mjs`, затем установите форк
   на отдельный профиль и проверьте живьём.
